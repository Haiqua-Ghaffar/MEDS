## Traffic Light Controller FSM
A traffic light controller is a classic example of a Finite State Machine (FSM) used to manage real-world timing and control systems.

### FSM Design Principles

#### State Definitions and Transitions
An FSM is defined by a set of states and rules that determine how the system moves from one state to another based on inputs.

### Hardware Implementation

#### State Transition Table
A state transition table maps current states and inputs to the next state, forming the basis for hardware implementation.

#### State Encoding
State encoding assigns binary values to each state so that the FSM can be implemented using digital circuits.

##### Trade-offs in State Encoding
Different encoding schemes (binary, one-hot, Gray) affect hardware complexity, speed, and power consumption.

#### Output Logic
Output logic determines system outputs based on the current state (Moore) or current state and inputs (Mealy).

#### Schematic Generation
Once the FSM is designed, it can be translated into a hardware schematic using logic gates and flip-flops.

---

### Timing and Reset

#### Asynchronous Reset
An asynchronous reset immediately forces the system into a known state regardless of the clock signal.

---

### Moore vs. Mealy Machines

#### State Encoding Strategies
FSMs can be designed using different state encoding methods depending on design goals.

#### Snail Example: Moore and Mealy
The snail example illustrates how Moore and Mealy machines can produce different output timing behavior.

#### Trade-offs Between Moore and Mealy
- Moore machines: outputs depend only on state, more stable  
- Mealy machines: outputs depend on state and inputs, faster response
